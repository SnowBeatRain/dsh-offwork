# 喝水提醒：自然时间规则

当前1.1.2按用户要求，将喝水提醒从工作时间、作息、薪资配置和会话中独立出来。此前按工作时间运行的规则只适用于历史版本。发布与升级说明见 [1.1.2发布记录](RELEASE-1.1.2.md)。

## 使用规则

- 默认关闭，默认间隔60个自然分钟，可设置5–240分钟整数；保留15/30/45/60/90/120分钟预设。
- 开启后按绝对截止时间计时。上班前、午休、下班后和休息日都能提醒，不等待下一班。
- 修改间隔、从关闭改为开启、手动恢复暂停时，按当前时间安排完整间隔。保存未变化的设置不延期。
- 改工资、作息、工作日或时区不会重排喝水计划；没有会话、未配置薪资、Host读取失败或正在读取时，喝水设置和操作仍可使用。
- 关闭卡片、刷新或切到后台不会重置截止时间。后台及关闭页面期间自然时间继续经过，但只有页面打开且可见时才能显示页面内提醒；不申请系统通知或声音权限。
- 多个周期过去后只保留一个待处理事件，不补发多条。到期提示的收起与Escape不记录、不延期；刷新时已逾期先显示小提示，保持此前的呈现规则。
- “喝了”确认当前到期事件，饮水计数加一，下一次从实际确认时刻起算；“10分钟后”按自然时间延期10分钟，不增加计数。
- “喝了一杯”可随时主动打卡。关闭提醒或暂停时只记录，不自动开启或恢复提醒；正常或免打扰期间打卡会重排完整间隔，免打扰结束时间保留。
- “暂停提醒”持续到手动恢复；不会因日期或班次变化自动恢复。恢复后重新安排一个完整间隔。
- 免打扰为30/60个自然分钟，可跨过下班时间和午夜。结束时若提醒已逾期只提示一次。暂停或关闭提醒会结束免打扰。
- 饮水计数延续现有记录，不再随班次或日期自动清零。清零需明确确认，只改变计数；重置当前提醒需确认，恢复关闭、60分钟和零计数。
- 打卡成功的角色反馈在空闲时间同样可播放；手动暂停、免打扰、减少动态效果、动作关闭和页面隐藏继续生效。播放结束不会再次计数。

## 数据、迁移与旧标签页

数据仍在同源浏览器IndexedDB `dsh.offwork-clock.hydration.v1`，不写入Host薪资文件、会话或远程服务。数据库名保留，数据库版本升至2，新记录使用`wall-clock`对象仓库、`current`键，记录schema为3。

原`state`仓库中的schema1/2记录保留，不覆写。首次读取新仓库时，在同一个跨仓库事务中完成迁移与`legacy-imported`标记：

- 保留开关、间隔、次数、暂停状态、仍有效的免打扰时间及近期操作ID，清除旧显示租约。
- 原记录仍对应同一班次且可解析时，将原剩余工作分钟一次性转换为从升级时刻开始的自然分钟；旧提醒已经逾期则保持到期。
- 旧记录属于过去班次或其时间信息不可还原时，从首次迁移时刻开始一个完整间隔，仍保留计数与暂停设置。不会猜测或补记过去的喝水记录。
- 迁移标记防止重复导入；以后显式重置或删除新记录也不会让旧次数复活。旧仓库仅为原始快照，正常运行不再读取。
- 旧客户端仍要求数据库版本1，会停止喝水操作而不能覆盖新记录。升级后应刷新所有已打开的Harness标签页；旧连接阻塞升级时可在关闭旧页后重试。

新记录只包含提醒开关、间隔、计数、暂停标志、截止时间、免打扰截止时间、事件序号、展示租约、修订号和最近64个手动操作ID。没有薪资、工作日、班次身份、会话ID或备注。

IndexedDB读写事务是多标签页的互斥边界，广播和轮询只负责同步显示。只有可见且未编辑的页面领取提醒；确认需再次核验事件和租约。手动操作ID与事件身份防止重试或同一到期事件重复计数。

存储失败、未知版本或损坏记录会停止自动提醒与修改，显示重试入口，不切换为多个内存副本或默默覆盖数据。不可读取时显示未知计数，避免把默认零误当成丢失记录。清除站点数据会删除本地计时与原始迁移快照。

## 验证

覆盖自然时间计时、午休/晚间/周末/午夜、稍后10分钟、长期暂停、免打扰跨下班、稳定逾期事件、手动与提示去重、租约接管、清零/重置、事务失败及schema1/2迁移。

实际隔离Harness浏览器验证旧/新客户端同源迁移及旧写入隔离、晚上与休息日到期、修改作息不改期限、午休继续计时、无会话/无薪资/Host失败与慢读、存储恢复、刷新及双标签只处理一次，以及休息日完整7.5秒喝茶反馈。

原工作时间方案调研保留在`hydration-research`中供追溯；不再作为当前产品规则。
