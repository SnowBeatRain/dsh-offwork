# 喝水提醒：开发与验收约定

状态：本地开发，尚未发布 npm。未来版本候选为 `1.0.2`，本轮保持 package.json、锁文件和客户端版本标记 `1.0.1` 不变，不推送、不打标签、不发布。按用户要求，`dsh.toolscc.cn` 的测试账号加载本地开发目录用于验收。

## 开发前调研

三个独立 Codex 子 agent 分别完成了[业务规则](hydration-research/business-report.md)、[浏览器与多标签页](hydration-research/browser-report.md)、[集成和验证](hydration-research/integration-report.md)调研。只读沙箱无法访问项目目录后，提供了筛选后的公开源码作为输入；报告为静态分析，没有读取用户配置、会话或凭据。研究完成后才开始实现。

采纳共同建议：复用 `calculate()` 的有效工作时间与班次边界；提醒独立存储；处理恢复、夜班和并发；不让提醒请求进入 Harness 会话。报告中的建议不是全部实施承诺，下列规则是本轮最终取舍。

## 首版规则

- 默认关闭，默认每 60 个工作分钟提醒，可设置 5–240 分钟整数。独立设置页提供 15 / 30 / 45 / 60 / 90 / 120 分钟预设及自定义输入。
- 开关和间隔先编辑，再统一点击“保存提醒设置”生效；支持回车提交和取消。面板显示当前已生效的间隔。
- 开启、修改间隔、恢复本班或修改作息时，从操作后的有效工作进度重新安排完整周期；薪资金额变化不重排。
- 第一次在新班次打开页面，从当前工作进度起算，避免打开就催促。班前启用从开工起算。非工作日和班后等待下一班。
- 午休期间冻结剩余工作时间且不显示提醒；“稍后”也是 10 个工作分钟，文案明确说明。
- 到期保留一个待处理事件；刷新、后台恢复或休眠跨过多个周期最多恢复一条，不补发多条。
- “喝了”只处理到期事件，次数加一，下一次从实际点击进度起算；同一事件重复操作不重复计数。
- “本班暂停”取消本班提示，保留次数，夜班零点不恢复；可手动恢复，下一班自动恢复。
- 修改同一班次作息会重排周期，保留次数和本班暂停；更换时区或班次开始日视为新的班次。首版仅保留当前/最近一个班次记录。
- “清除本班次数”需确认，仅把次数归零，不改变下一次提醒或暂停状态；“重置喝水提醒”需确认，恢复关闭、60 分钟、无记录。
- 工资设置与提醒设置使用独立页面和表单，各自只有对应的保存入口。提醒设置通过“保存提醒设置”提交，不受工资表单影响；取消或返回不会保存草稿。

## 数据与协调

使用独立 IndexedDB 数据库保存偏好和一个班次记录。IndexedDB 事务为多个标签页的读取、更新和事件领取提供原子性，不使用 `localStorage` 伪锁。记录包含 schema 版本、修订号、班次身份、作息指纹、下一次到期进度、事件序号和短期展示租约。

只有可见标签页能领取提醒；隐藏、卸载或失去有效班次时释放。显示权以事务租约为准，定期续租，处理按钮需再次校验事件与所有权。广播用于及时通知重新读取，事实来源仍是事务存储。进程冻结/崩溃后允许其他标签接管；恢复时先校验，不声称冻结的屏幕画面永远实时一致。

IndexedDB 不可用或中途写入失败时停止自动提醒及持久操作，显示明确提示；不自动切换为可能重复提醒的多个内存副本。未知版本或损坏数据不静默覆盖，用户可明确重置喝水提醒数据。数据库与数据记录都不包含薪资、会话 ID 或备注。

同一浏览器、同一站点共享提醒数据；不跨浏览器/设备同步。页面关闭后不继续提醒，不申请系统通知或声音权限。

## 验收

自动化覆盖午休冻结、稍后跨休息、夜班跨午夜、休息日、DST、超时恢复、设置修改、重复点击、并发领取和数据恢复。真实 Harness 浏览器验证覆盖默认关闭、开启、即时设置、倒计时、三个操作、刷新、双标签页、隐藏/关闭接管、清除/重置、窄屏及原有工资交互。

交付包含本地开发分支、验证记录和截图。由用户验收后再决定版本更新、合并与发布。
