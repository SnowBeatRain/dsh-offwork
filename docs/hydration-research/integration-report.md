## 集成与验证建议

说明：以下结论仅基于题目提供的公开源码摘录；未访问仓库文件系统，也未执行测试。保持当前 `1.0.1` 版本号及发布状态不变。喝水提醒可作为候选 `1.0.2`，仅在用户验收后再改版本、合并或发布。路线图中的 `1.1.0` 应在实施前同步修订，避免文档与交付版本冲突。

### 最小集成边界

1. 新建纯提醒状态机模块，和 `clock.js`、`ui-utils.js` 同级。
   - 输入：`now`、`calculate()` 的班次结果、提醒偏好、当前班次记录、上次处理事件。
   - 输出：规范化状态、下一触发时间、是否产生一个待提示事件，以及状态变更意图。
   - 不读取 DOM、React、`localStorage` 或远程命令；不自行启动定时器。
   - 复用 `calculate()` 返回的 `status`、`shiftDate`、`shiftStart/End`、`breakStart/End`，不要复制夜班、时区、DST 和工作日算法。
   - 班次身份至少包含时区和 `shiftDate`，最好再含 `shiftStart`，避免零点后“本班暂停”失效。
   - 状态机只在 `working` 计时；`before/rest/lunch/done` 不触发。午休结束后按明确规则恢复，不能补发午休内每个周期。
   - 恢复或休眠错过多个周期时最多合并为一个事件。
   - “喝了”从实际完成时间重排；“稍后”从操作时间重排；“本班暂停”持续到班次身份变化；关闭后清除待显示状态。

2. 新建独立浏览器存储适配层。
   - 使用新 key，例如提醒偏好和提醒运行记录各自独立；不得写入工资 `data.json`，也不得调用 Harness 会话命令。
   - 数据包含显式 `schemaVersion`，读取时进行白名单校验、默认值补齐和迁移。
   - 偏好与班次记录分离：偏好可长期保留；次数、暂停、事件领取按班次标识保存。
   - 存储不可用时退化为当前页面内存状态，并向用户明确提示；不能因此破坏工资悬浮窗。
   - “清除本班记录”只删除当前班次计数、暂停及待处理事件，不应清除工资设置、位置、透明度或金额隐藏偏好。
   - “重置提醒数据”应有确认步骤，并精确删除提醒命名空间。

3. `tools/build.mjs` 只需将新增纯模块加入内联模块清单。
   - 保持“Node 单测导入的源文件与浏览器产物运行同一实现”的现有约束。
   - `client.js` 仍为生成物；开发只改源文件和纯模块。
   - 构建检查应继续证明产物未过期。

4. React 集成集中在 `Clock` 内的一个提醒控制器 Hook 或小型状态组合。
   - 使用现有每秒 `now` 与 `visibilitychange` 恢复机制驱动重新计算，不另建多个相互漂移的秒级定时器。
   - 注册 `storage`、`visibilitychange`、可选 `BroadcastChannel`、定时器后，都必须在 effect cleanup 中注销或关闭。
   - 插件卸载、会话切换和组件重挂载不得遗留提示、事件监听或后台写入。
   - 提醒与 `sessionId` 无关；没有会话或工资远程读取失败时，只要已有有效作息，提醒不应被无关 RPC 阻塞。

### 多标签页去重

仅监听 `storage` 事件不足以保证原子去重：该事件不会在写入它的同一标签触发，多个标签也可能同时读到“未领取”并各自展示。

建议采用带租约的事件记录：

- 状态机生成稳定 `eventId`，包含班次身份和计划触发时间。
- 标签尝试写入 `{eventId, ownerId, claimedAt, expiresAt}` 后立即回读确认所有权。
- 展示前再次核对所有权；操作后写入最终处理结果。
- `storage` 事件负责同步其他标签；`BroadcastChannel` 可降低延迟，但不能作为唯一持久化依据。
- 租约过期允许其他标签接管，以处理原标签崩溃。
- 所有写入都应重新读取并合并较新状态，避免“最后写入覆盖”丢掉另一标签刚完成的打卡。
- 需要明确同毫秒竞争测试；若无法给出可靠领取协议，首版不应声称完成多标签页去重。

### 现有代码风险

- 视图状态先以默认值渲染，随后异步 effect 才读取 `localStorage`。提醒默认关闭虽然可防误弹，但仍需设置 `reminderReady` 门槛；完成读取前禁止调度、写回默认值和展示提示。
- 现有视图 effect 在 `ready` 后会写回全部 `view`，同时 `storage` 事件也会 `setView`。跨标签更新可能触发回写回声或覆盖近同时修改；提醒存储不要照搬整对象“读后全量覆盖”模式。
- 浏览器 `storage` 事件可能携带 `newValue === null`，也可能收到旧版本或损坏 JSON；必须校验后再迁移，不能静默当成有效默认值并立即覆盖。
- `reload()` 的 `requestBusy.current` 实际没有在读取流程置为 `true`，不能把它当通用并发锁。提醒需要自己的串行化/领取机制。
- `generation.current` 能抑制过期 RPC 回写，但不能取消本地存储竞争、已排队微任务或跨标签事件；提醒生命周期需独立的活动标记和清理。
- 当前 `now` 在隐藏页面时停止逐秒更新，返回可见时刷新。这适合提醒，但状态机必须按真实 `Date.now()` 合并遗漏周期，不能依赖 tick 次数累计。
- `calculate()` 将夜班归属到班次开始日，提醒不得用浏览器当前自然日重置次数或暂停。
- 午休属于 `lunch`，但 `remaining` 仍指向下班时间；提醒不能根据剩余秒数推断是否应运行。
- 拖动监听挂在整个 section 上。提示按钮、表单控件必须继续落入排除选择器；新增控件类型也要加入，否则点击可能启动拖动。
- 展开编辑器当前会自动聚焦第一个工资表单控件。提醒到期不得切换到编辑态或抢焦点。
- 外层存在 `user-select:none`、固定宽度和最大高度；提示文本及操作按钮需验证键盘、缩放和窄屏，不可依赖单行布局。
- `messages` 为中英文内联字典。新增文案必须两种语言同时补齐，避免返回 key、混合语言或用字符串拼接形成不自然语序。
- `data-version="1.0.1"` 与 `package.json` 均应在研究及预览阶段保持不变；不能用界面属性暗示已发布 `1.0.2`。

### 设置与提示界面

- 设置页增加独立“提醒”分组，不放进“薪资”字段集，也不随工资保存按钮调用远程 `set`。
- 提醒开关、间隔、稍后时长和清除本班记录均直接写独立本地存储。
- 保存语义必须清晰：若仍共用一个“保存”按钮，应分离远程工资保存失败与本地提醒保存结果；更稳妥的是提醒设置即时保存并显示本地状态。
- 小条仅在启用后显示简短的下次提醒倒计时；关闭后恢复现有尺寸与行为。
- 到期提示应位于现有 overlay 内，使用语义化区域，例如 `role="status"` 或非强制的命名区域；不要使用会抢焦点的模态框。
- “喝了”“稍后提醒”“本班暂停”和关闭均使用原生按钮，提供完整可见文字或准确 `aria-label`。
- 提示出现时不自动聚焦；用户可用 Tab 到达操作，用 Enter/Space 激活，Escape 仅关闭当前提示且不等同于关闭提醒。
- 操作完成后将焦点保留在合理位置；若原按钮消失，应回到悬浮窗标题或稳定控制。
- 状态变化通过克制的 `aria-live="polite"` 通知；每秒倒计时不要持续播报。
- 320px 宽视口、200% 缩放、长英文/中文文案下允许换行，操作区可纵向排列，内容区可滚动且关闭按钮始终可达。

### 纯模块单元测试矩阵

- 默认关闭、开启初始化、无有效作息输入。
- 工作前、工作中、午休、下班后、休息日。
- 日班与跨午夜夜班，夜班零点前后班次身份一致。
- 工作日按班次开始日判断。
- 有无午休；提醒恰好在午休开始、结束和班次结束边界。
- DST 跳时与重复小时，直接复用 `calculate()` 的绝对时间结果。
- “喝了”从操作时刻重排；“稍后”从操作时刻重排；暂停到下一班自动解除。
- 刷新前后状态一致；错过一个和多个周期都只产生一次提示。
- 系统时间向前大跳、向后回拨，不产生提示风暴或重复事件。
- 相同输入输出完全一致，不读取全局时间。
- 损坏、缺字段、未知版本、非法间隔、过大记录的修复或拒绝策略。
- 清除当前班次与清除全部提醒数据的范围准确。
- 稳定 `eventId`、重复处理幂等、已完成事件不再展示。
- 两标签同时领取、租约接管、处理结果合并、不丢计数。

### 浏览器与真实 Harness 验证矩阵

- Harness `0.2.1-rc.5`：安装候选包、首次启用、刷新恢复、禁用后工资与倒计时回归。
- 双标签同时到期只显示一次；关闭获胜标签后另一标签可接管过期租约。
- 标签后台节流、系统休眠、恢复可见，最多出现一个合并提示。
- 午休前进入后台、午休后恢复；不补发午休期间周期。
- 夜班跨零点、本班暂停跨零点、下一班恢复。
- 切换 Harness 会话、无会话、远程工资读取失败时提醒边界正确。
- `localStorage` 禁止、配额失败、损坏数据、另一标签清除数据。
- 点击、Tab、Shift+Tab、Enter、Space、Escape；提示出现时输入框焦点不丢失。
- 拖动、缩放窗口、ResizeObserver 重排后提示仍在视口内。
- 320×568、窄 Harness 侧栏、200% 缩放、中英文切换、长时区名称。
- `prefers-reduced-motion`、高对比度、降低透明度模式。
- 提醒关闭后的 DOM、监听器、定时器和存储写入均停止。
- 工资隐藏、透明度、位置、薪资保存、跨午夜工资计算保持原行为。
- Chromium 为最低覆盖；条件允许时补 Firefox/WebKit，尤其验证 `storage`、后台节流和焦点行为。

### 隔离预览方案

- 从当前基线创建独立开发工作树或临时副本，使用独立分支和独立包名/插件 id，例如 `dsh-offwork-hydration-preview`。
- 预览插件使用独立 overlay slot id、独立浏览器存储前缀及独立 Harness 数据目录，避免与已安装正式插件冲突。
- 通过本地打包产物或 `npm pack --dry-run` 后生成的临时候选包安装到隔离 Harness 配置目录，不执行发布。
- 不修改正式插件 `main`、不替换线上安装、不读取或复制真实 `data.json`。
- 使用固定的虚构工资和班次测试夹具；浏览器 profile 也应独立。
- 预览 UI 明确标注“本地候选”，但不修改正式版本号。用户验收通过后，才决定将候选整理为 `1.0.2`、更新路线图/变更日志并进入正式发布流程。

建议把验收门槛设为：纯状态机规则冻结、双标签去重可重复验证、真实 Harness 回归通过、窄屏与键盘无阻断、数据清除范围经人工确认。上述条件完成前，不应调整 `1.0.1` 或承诺发布 `1.0.2`。
