## 使用者需要反馈的内容

刷新当前服务器上的 Harness 页面，用现有插件检查以下操作：

1. 小条和展开详情正常显示，倒计时持续更新。
2. 展开 / 收起、拖动及缩小浏览器窗口正常，不遮住重要操作。
3. 工资显示 / 隐藏及背景透明度设置正常，设置中的薪资也同步遮蔽。
4. 保存作息后能读回配置，刷新后配置和显示偏好保留。
5. 使用过程中没有持续出现错误提示。

反馈可以直接按以下格式填写；没检查的项目写未验证：

```text
操作系统：
浏览器与版本：
Harness 版本（不确定可留空）：
倒计时与详情：正常 / 异常 / 未验证
拖动与收起：正常 / 异常 / 未验证
金额遮蔽与透明度：正常 / 异常 / 未验证
保存与刷新恢复：正常 / 异常 / 未验证
问题及复现步骤：
```

首次安装引导、键盘操作、夜班和多标签页等额外场景，按 CONTRIBUTING.md 的步骤继续验证，不能用以上几项通过替代全部场景的结论。

## 截图要求

- `assets/screenshot-compact.png`：默认小条，显示其在实际 Harness 页面中的位置。
- `assets/screenshot-detail.png`：展开详情，能看见计薪进度、日薪 / 时薪等布局。
- `assets/screenshot-settings.png`：设置页，展示薪资模式、作息和透明度等选项。
- 工资可保持隐藏；若展示金额，使用示例数据。裁掉会话内容、账号信息和其他个人资料。
- 图片体现实际插件效果，保持文字清晰，不添加不存在的功能。

收到截图后再整理文件、在根目录添加真实的 `screenshots.json`，并将图片嵌入 README。当前不创建指向尚不存在图片的声明。

## 发布与投稿顺序

1. 整理浏览器反馈；发现问题先修复并重新验证对应场景。
2. 加入三张真实截图及说明，核对 npm 发布包与当前文档。
3. 执行 `npm run check`，提交源码与素材。
4. 更新到 `1.0.1`，推送版本标签，通过现有 GitHub Actions 发布；确认公共 npm 元数据和压缩包可用。
5. 核对 awesome-dsh-plugin 的实时指南、已有条目和开放 PR，避免重复投稿。
6. 向对方新增一条 YAML，保留准确的中英文描述，声明已准备的 PNG 图标。
7. 仓库创建满一天的时间为 `2026-11-05T11:39:22Z`，即北京时间 2026 年 11 月 5 日 19:39:22。此前准备材料，之后提交。
8. 收录由维护者审核决定；合并与目录更新后，再核实市场中是否可搜索、是否能正确安装。

公开社区介绍采用 `docs/PROMOTION.md` 的文字，选择实际使用的社区发布。市场未收录时，不使用“已上架”等表述。
